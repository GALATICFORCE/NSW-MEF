# MEF 标签规则 v1（草案，待周三确认）

## 0. 声明

- **起草者事先看过的 MEF 数值**：2026H1 "丢弃"和"记为 0"两种处理下的分小时 MEF 均值；2025-07 至 2026-06 两种处理下的月度 MEF 均值；调试时个别区间的 MEF 值；5 分钟表验收第 5 项给出的 mef_nemed 全年最大值、最小值和分位数。
- **起草依据**：只用验收第 8 项的方向分布表（`data/processed/check8_share_2025H2.csv`、`check8_share_2026H1.csv`），以及只由 status、batt_dir、时间戳算出的计数。没有计算任何 B/C 标签。
- **窗口边界是看过全年方向分布之后定的。**

## 1. 输入与时间约定

- 输入：`data/processed/mef_nsw1_5min_full.csv`，列定义见验收回复。
- 区间开始时刻 = Time − 5 min，NEM 时间（AEST，UTC+10，不调夏令时）。小时和窗口按 NEM 时间判断。
- **预测日**：区间开始时刻换算成悉尼本地日期（Australia/Sydney）。
  - 研究期内，夏令时（AEDT）覆盖 NEM 时间 2025-10-05 02:00 到 2026-04-05 01:55。
  - 这段时间里，NEM 23:00–24:00 的区间属于下一个悉尼日期，共 2,184 个，其中电池定价 411 个。
- **窗口段** = （预测日，窗口）。夏令时期间，晚间放电窗口被日界切开：NEM 23 点那一小时，成为下一个预测日开头的一个单独窗口段。
- 三个标签：
  - `mef_A`：电池记为 0。只作参照，不做主标签。
  - `mef_B`：同窗口反事实。
  - `mef_C`：充放电折算反事实。

## 2. 窗口

**规则**：在每个 NEM 小时里，看电池定价区间（status 为 batt 或 mixed）中充电占多数（>50%）还是放电占多数；把多数方向相同的连续小时连成一个窗口。

`charge` 的占比 = (batt_charge + mixed_charge) / (batt + mixed)。只用 batt 区间计算，每个小时的多数方向不变。

| 窗口 | 类型 | 2025H2 | 2026H1 |
|---|---|---|---|
| 凌晨 | 充电 | 01:00–04:00 | 00:00–05:00 |
| 早高峰 | 放电 | 04:00–08:00 | 05:00–07:00 |
| 白天 | 充电 | 08:00–16:00 | 07:00–16:00 |
| 晚间 | 放电 | 16:00–01:00（跨午夜） | 16:00–24:00 |

两套只在 0 点、4 点、7 点三个小时上不一致：

| 小时 | 2025H2 充电占比 | 2026H1 充电占比 | 电池区间数（H2 / H1） |
|---|---|---|---|
| 0 | 0.390 | 0.538 | 213 / 398 |
| 4 | 0.404 | 0.582 | 228 / 498 |
| 7 | 0.420 | 0.574 | 462 / 1,114 |

三个小时都是充放电的过渡段，占比都在 0.39–0.58 之间。

**主方案：全年统一用 2026H1 这一套。** 理由有三条：

1. 2026H1 的电池定价区间是 23,021 个，2025H2 是 10,845 个，标签受电池处理影响的区间约三分之二在 H1。
2. 2026H1 更接近当前的电池规模。
3. 把 H1 这套用到 H2，只有 903 个区间落在多数方向相反的小时里；反过来把 H2 这套用到 H1，会有 2,010 个。

**敏感性分析**：两个半年各用自己那一套。

四个窗口覆盖全天 24 小时，没有落在窗口之外的区间。

## 3. 来源区间与窗口值

- **来源区间**：同时满足 `status == nonbatt`、`ef_missing == False`、`has_ldof == False`，共 70,875 个。
- **窗口值** S(段) = 该窗口段内所有来源区间的 `mef_nemed` 均值。
- **待定**：来源区间是否再加一条 0.5 ≤ w_enof ≤ 1.5（w_enof 不含 Basslink），见第 9 节第 1 条。

## 4. 配对（只在同一个预测日内）

- **B**：电池记录取它所在窗口段的值，充电和放电都一样。
- **C，放电记录（BDOF,GEN）**：
  - 区间落在充电窗口里，就取这个窗口段；
  - 否则，取同一预测日内、在它之前结束的最近一个充电窗口段。
- **C，充电记录（BDOF,LOAD）**：
  - 区间落在放电窗口里，就取这个窗口段；
  - 否则，取同一预测日内、在它之后开始的最近一个放电窗口段。

**C 的物理含义**：按"放电配之前的充电"来配对，等于假设电池的充放电在**同一个预测日内**收支平衡。也就是说，多放的电由当天早些时候多充的电提供，多充的电在当天晚些时候多放出去。这和"放完之后再补充"的说法不同；后者通常要跨到下一天，与"不跨日"的要求冲突。

**过渡小时**：7 点和 15 点充电、放电都相当常见。这两个小时里的配对，按上面的规则会落到所在窗口本身，结果对窗口边界比较敏感。

## 5. 兜底

N = 6，相当于 30 分钟的来源区间。依次尝试下面三档，第一档满足 ≥ N 个来源区间就用该档的均值：

| 档 | B 用的来源 | C 用的来源 |
|---|---|---|
| 1 | 所在窗口段 | 按第 4 节配对到的窗口段 |
| 2 | 同一预测日内、与所在窗口同类型的所有窗口段 | 同一预测日内、所需类型的所有窗口段（放电记录用所有充电段，充电记录用所有放电段） |
| 3 | 同一预测日内所有来源区间 | 同一预测日内所有来源区间 |

- 三档都不满足 ≥ N 时，该值为 NaN。
- 每个标签都另记一列，写明实际用了第几档（`tier_B`、`tier_C_gen`、`tier_C_load`）。
- 典型情形：夏令时期间，预测日开头那一小时的放电记录，在当天找不到"之前"的充电段，会直接进入第 2 档。

## 6. 标签公式

沿用 nemed 的合成方式：强度 = Σ（Increase × 排放因子），不归一化。只把电池记录的排放因子换成反事实值：

```
base   = mef_nemed     （status 为 nonbatt 或 mixed）
       = 0             （status 为 batt）
mef_X  = base + w_gen × EF_gen^X + w_load × EF_load^X
```

| 标签 | EF_gen | EF_load |
|---|---|---|
| A | 0 | 0 |
| B | S(所在段) | S(所在段) |
| C | S(配对的充电段) ÷ η | η × S(配对的放电段) |

- nonbatt 区间的 w_gen = w_load = 0，三个标签都等于 mef_nemed。
- batt_dir = both 的区间不需要单独处理：GEN 和 LOAD 两侧各用各的排放因子。任一侧需要的值是 NaN，整个标签就是 NaN。
- Increase 为负的电池记录（`n_neg_batt`）按原符号计入，和 nemed 对 ENOF 负值的处理一致。
- η = 0.85（待核实）。敏感性分析取 0.80 和 0.90，只影响 C。

## 7. 置为 NaN

以下区间的 A/B/C 标签全部为 NaN，共 384 个：

- status 为 other 或 norecord；
- has_ldof 为真；
- ef_missing 为真。

另外，第 5 节三档兜底都不满足的值也是 NaN。

## 8. 结论分级

- **稳健结论**：在 B 和 C 下都成立。
- **依赖储能假设**：只在 C 下成立，在 B 下不成立。必须标注。
- A 只作参照，不用于给结论分级。

## 9. 待定事项（周三讨论）

1. **w_enof 目前包含 Basslink 的 ENOF 记录，nemed 计算时会把它去掉。**
   - 有 2,695 个 nonbatt 区间出现了 Basslink 的 ENOF 记录。
   - 有 863 个 nonbatt 区间 w_enof = 0，其中 862 个是 Basslink 记录抵消造成的。
   - 建议 w_enof 不含 Basslink，另加一列 `w_basslink`。
   - 去掉 Basslink 后，nonbatt 区间的 w_enof 在 1% 到 99% 分位之间是 0.871–1.258，落在 [0.5, 1.5] 之外的有 151 个区间。是否把这 151 个排除出来源区间，需要你们定。
2. **是否增加 `has_basslink` 标记。** nemed 等于把 Basslink 的贡献当成 0，这和 ef_missing 是同一类"悄悄记为 0"的问题。
3. **nonbatt 区间本身的极端值**（不在 B/C 规则范围内，对 A/B/C 影响相同）：
   - mef_nemed < 0 的有 256 个，> 1.5 的有 88 个。
   - 来源是 nemed 不归一化的求和：方向相反的大 Increase 互相抵消，或者同价机组的 Increase 被重复计入。
4. **7 点和 15 点的配对方式**（见第 4 节）。
